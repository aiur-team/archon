# AHU-001 — Establish hosted service boundaries and executable contracts

**Kind:** executable

**Provenance:** planned in plan v1

**Complexity:** 3 — One self-contained app skeleton, executable validation contract and CI deployment seam; no authentication implementation.

**Risk:** high — Every later trust boundary consumes these defaults.

**Phase hint:** 1

**Requirements:** R2, R3, R4, R6, R7, R8, R9, R10, R11, R14, R15

**Researched at:** dfbd7a7ed2bfb0b2f1742e1d1e2294ab599d1b79

## Outcome

Parallel workers can import one tested hosted contract and build the new deployment without changing self-hosted behavior.

## Context and evidence

Read [contracts](../contracts.md), [authentication research](../research/authentication.md), and [hosting research](../research/hosting-security.md).
The existing root `netlify.toml` runs `templates/build --site` and the legacy gate on all paths.
`scripts/connect.mjs` copies that deploy tree into customer sites.
`netlify/lib/access.mjs:550` requires an email-seeded owner; `netlify/lib/identity.mjs:48` returns a Netlify subject.
Those are existing self-hosted contracts, not suitable defaults for identity-only shared uploads.
`.github/workflows/check.yml` loads root server imports before builder compilation and explicitly enumerates tests; new hosted modules need the same guarantee.

## Scope

- Create NEW `hosted/package.json`, lockfile, `hosted/netlify.toml`, `hosted/lib/contracts.mjs`, `hosted/lib/config.mjs`, and `hosted/lib/contracts.test.mjs`.
- Establish NEW empty trusted app shell `hosted/public/index.html`, with no production upload route enabled.
- Implement descriptor, ID, origin, state, safe-error and result-envelope validation; export constants matching contracts C1–C6.
- Provide deterministic non-secret fixtures in NEW `hosted/test/contract-fixtures.mjs` for every allowed response state and malformed alternatives.
- Add NEW `scripts/check-hosted-modules.mjs` to load all hosted function imports without invoking handlers or live providers; path scans cannot escape the hosted deploy root.
- Wire contract tests and the hosted clean-install/module gate into actual run steps in `.github/workflows/check.yml`; extend inventory discovery if the existing checker does not discover the hosted root.
- Publish exact module/export names in the producer PR for sibling import consumers. Ticket contracts remain the agreed data semantics.

## Non-goals

No OAuth exchange, session implementation, publication storage, renderer implementation, publishing command, provider signup, or deployment.
No change to root deployment, existing role validators or legacy scripts.
Do not introduce a generic framework, monorepo manager or npm library for a handful of shared records.

## Existing owner and reuse target

Reuse the module-load gate's early-linking principle and Node's built-in tests.
Reuse the tested strong-write/error taxonomy pattern from `netlify/lib/store.mjs` as a design reference only; AHU-004 owns the hosted adapter.
Keep hosted modules self-contained instead of importing legacy role policy or generated builder output.
There is no existing hosted app directory: every path above is new, except CI and inventory integration.

## Contract and invariants

The producer implements the full [contracts v1](../contracts.md), not a second alternative schema.
C1 defines deployment and identity; C2 record/descriptor; C3 wire errors; C4 read/message shape; C5 client outputs; C6 configuration.
Export `validateDescriptor`, `validatePublication`, `validateResult`, `validateOrigin`, `HOSTED_LIMITS`, and `PUBLICATION_STATES` from `hosted/lib/contracts.mjs` (new proposed exports).
Validation returns a validated value or a typed invalid-input error; unavailable backing services are never validation success.
`hosted/lib/config.mjs` exports `readHostedConfig(env)`, returning trusted app/render origins, OAuth configuration and publish-enabled boolean with secrets redacted from formatting.
Pure validators have no network, clock or process-global mutation.
Fixtures may be imported by tests but never supply production responses or fake success.
C2 allows nullable fields only in their prescribed states: complete requires owner, HTML, completion and receipt timestamps; pending cannot contain HTML/owner; approved requires owner/upload deadline but no HTML.
Missing/unknown fields and unexpected owner claims are rejected at their public input boundary.
Builder package consumes the wire contract through its own typed validation; it must not import server secrets or server-only modules.

## Refreshable implementation notes

Inspect the current inventory checker before extending it; preserve explicit-test execution rather than making a filename mention enough.
Use package-scoped installation and no generated-builder imports at function cold start.
Config validation must allow safe fixture injection without production bypass flags or defaults pointing at guessed domains.
Deploy skeleton defaults to publishing disabled; AHU-011 adds tested rate-limit and operational behavior using the same config owner.
A route can be absent until its producer lands; never put placeholder success handlers in production.

## Acceptance and verification

### Agent gate

- `npm --prefix hosted ci --ignore-scripts --no-audit --no-fund`, `node scripts/check-hosted-modules.mjs`, and `node --test hosted/lib/contracts.test.mjs` execute without compiling docbuild or credentials.
- Valid 1-byte-boundary descriptors and 2,097,152-byte limit pass; oversized, empty, malformed SHA/UTF-8 metadata, non-HTTPS production origins, equal app/render site, owner injection and unknown states fail.
- Complete fixture lacking owner or HTML fails; approved fixture with HTML fails; error envelope cannot pass result validation.
- Remove each validator condition in an isolated test checkout and demonstrate the guarding test fails; restore and pass.
- Root deploy module gate and legacy inventory behavior remain intact.

### At-merge gate

Current-base CI passes with explicit new commands. Check package lockfile matches package manifest.
Consumer import contract is present in the actual source, not just a ticket comment.
No live provider action or service account required for these gates.

## Failure, security, migration, and accessibility cases

Malformed configuration fails closed; no fallback from unknown origin to request Host headers.
Secrets do not appear in config exceptions, fixture snapshots, stdout, source bundles or git.
Two origins means different registrable sites in production, not just sibling subdomains.
Use pinned `tldts@7.4.12` with private suffixes enabled for this comparison; reject IPs and indeterminate domains in production. Do not compare the last two hostname labels. Source: [upstream API](https://github.com/remusao/tldts), npm version checked 2026-09-09. Explicit loopback-only injected test configuration is separate from production parsing.
No legacy data migration is performed.
The skeleton page has semantic heading/title and explains unavailable publishing without implying authentication success; detailed UX is AHU-007/AHU-009.
